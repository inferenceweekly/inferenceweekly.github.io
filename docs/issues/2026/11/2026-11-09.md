# #2: This week in inference

Huge congratulations to the fal.ai on their [new funding round](https://www.bloomberg.com/news/articles/2026-11-03/ai-inference-startup-fal-raises-capital-at-16-billion-valuation/). Wishing you all the best as you keep scaling.

## :material-book-open-variant: Read

- **[Introducing Kinference: An Open Source Inference Control Plane for vLLM and Kubernetes | vLLM Blog](https://vllm.ai/blog/2026-11-04-introducing-kinference)**, *vllm.ai*.
    - Kinference puts rate limiting, cost tracking, cache-aware load balancing, and policy-based routing in front of vLLM on Kubernetes, so you can send simpler prompts to cheaper models.

- **[Benchmarking tiered KV cache offloading on H100 GPUs in OpenShift AI 3.5 | Red Hat Developer](https://developers.redhat.com/articles/2026/11/02/benchmarking-tiered-kv-cache-offloading-h100-gpus-openshift-ai-3-5)**, *developers.redhat.com*.
    - Offloading KV cache to CPU memory and NVMe/CephFS cut time to first token from ~60 s to ~10 s and raised throughput up to 5.8x on long-context agentic workloads, since cached prefixes are restored from storage instead of recomputed.

- **[How NVIDIA Uses AI Agents to Streamline AI Factory Operations | NVIDIA Technical Blog](https://developer.nvidia.com/blog/how-nvidia-uses-ai-agents-to-streamline-ai-factory-operations/)**, *developer.nvidia.com*.
    - NVIDIA's AI Factory Operations Agent coordinates specialist sub-agents to correlate root causes across compute, network, hardware, and scheduling, and its production lessons are to keep agent boundaries clear, start read-only to build trust and show reasoning so SREs can check evidence before acting.

- **[The Iron(wood) Throne: Google's TPU Stakes Its Claim on Inference](https://newsletter.semianalysis.com/p/tpu-strikes-the-king)**, *newsletter.semianalysis.com*.
    - SemiAnalysis finds Google's TPUv7 (Ironwood) competitive with NVIDIA on perf per dollar for long-context agentic inference, though NVIDIA FP4 still wins in some cases.

- **[What is NVKE | NVIDIA Kubernetes Engine](https://docs.nvidia.com/nvke/documentation/overview/what-is-nvke)**, *docs.nvidia.com*.
    - NVKE is an open-source system for running managed Kubernetes clusters on your own GPU machines, aimed at AI factory operators who offer AI and inference workloads to customers.

## :material-youtube: Watch

- **[The Context ft. Obot AI](https://www.youtube.com/watch?v=Qv17qmKhL78)**, *Agentic AI Foundation*.
    - Obot AI shows how to run self-hosted Claude environments on your own Kubernetes with sandboxed sessions, egress policies, and gateway-level audit logs of every API request and tool call.

- **[AIs Could Attack The Inference Engine To Escape Sandboxes | James Mickens (Harvard University)](https://www.youtube.com/watch?v=v-jq1pIKWEc)**, *FAR․AI*.
    - James Mickens argues that a misaligned model could escape its sandbox by exploiting the inference engine itself: it can fingerprint the engine through quirks like Unicode normalization, trigger a bug just by generating specific tokens, and potentially pivot to the host's bare metal

- **[How Inference Keeps Up with Our Insatiable Need for Tokens — Cerebras & Gimlet Labs](https://www.youtube.com/watch?v=_cRgl3maiT8)**, *AI Engineer*.
    - Scaling inference to meet token demand comes down to easing the memory-bound decode phase and KV cache, then splitting prefill and decode across pools and hardware tuned for each.

## :material-github: Repos

- **[Kinference-AI/kinference](https://github.com/Kinference-AI/kinference)**
    - Kinference is an alpha-stage control plane for vLLM on Kubernetes that routes and load-balances requests by policy and watches KV-cache state, configured through CRDs.

- **[dsx-ai-factory/nvke](https://github.com/dsx-ai-factory/nvke)**
    - NVIDIA's open-source, control plane for creating isolated Kubernetes clusters on bare-metal GPU machines, built on Cluster API and SPIFFE/SPIRE

- **[obot-platform/obot](https://github.com/obot-platform/obot)**
    - Obot is an open-source platform for governing AI use in an organization, with MCP and LLM gateways, access controls, audit logs, and Claude environments that run on your own Kubernetes.
