# #3: This week in inference
The PyTorch Conference videos are out, and there are tons of great inference talks in there. Worth a look if you have some time.

Also, Agent Substrate has released 1.0.0, [announced by Jaana Dogan](https://x.com/rakyll/status/2120646708577354113), and its KubeCon North America talks are now available too.

## :material-book-open-variant: Read

- **[Encoder Disaggregation in vLLM: Scaling Multimodal Serving with EPD](https://vllm.ai/blog/2026-11-11-encoder-disaggregation-epd)**, *vLLM Blog*.
    - Multimodal serving gets its own Encoder/Prefill/Decode split in vLLM, so media encoding scales on its own
- **[The six layers of an LLM inference system: from capacity to service](https://inferenceops.io/the-six-layers-of-an-llm-inference-system-from-capacity-to-service/)**, *InferenceOps.io*.
    - Builds an LLM inference system one piece at a time, placing each part on a six-layer stack from GPU capacity to service
- **[How LLM Serving Works: From One Request to a GPU Cluster](https://inferenceops.io/how-llm-serving-works-from-one-request-to-a-gpu-cluster/)**, *InferenceOps.io*.
    - A beginner-friendly tour of what happens between a user's request and the GPU: routing, queueing, scheduling, batching.
- **[A day in the life of an NVIDIA H100 on Red Hat OpenShift 5](https://developers.redhat.com/articles/2026/11/13/day-life-nvidia-h100-red-hat-openshift-5)**, *Red Hat Developer*.
    - Walks through Kubernetes dynamic resource allocation on a single H100, showing how three teams share one GPU on OpenShift 5
- **[[2611.16180] Fast Serverless LLM Cold Starts by Sharing and Prewarming Startup Work](https://arxiv.org/abs/2611.16180)**, *arxiv.org*.
    - Weight loading is only 5-11% of an LLM cold start. Cairn removes the rest by sharing compile and setup work through a CXL memory pool

## :material-youtube: Watch

- **[Inference Engineering Is the Most Important AI Skill Right Now: The 4-Layer Stack](https://www.youtube.com/watch?v=UHGCKoTvohU)**, *Vizuara*.
    - Inference is more than tokens on a screen. Here's the four-layer stack, from KV cache and MoE up to vLLM, parallelism and FlashAttention
- **[Fast, Small, Accurate: Optimizing Models for Inference using... - Zhiyu Cheng US & Trenton Starkey](https://www.youtube.com/watch?v=u3JQEAMfKC4)**, *PyTorch Foundation*.
    - A practical guide to FP4 quantization for faster, smaller models.
- **[Stop Shipping LLM Settings That Only Win on Paper - Rohan Pandey & Balaji Varadarajan, DigitalOcean](https://www.youtube.com/watch?v=cWrYEBlWpcY)**, *AI Engineer*.
    - Most LLM serving 'wins' come from tweaking one setting and don't hold up. This is how DigitalOcean tests configs against real latency targets

## :material-github: Repos

- **[hpdss-group/KVServe](https://github.com/hpdss-group/KVServe)**
    - KVServe is a vLLM KV connector extension that compresses KV-cache traffic in disaggregated prefill/decode serving, picking a compression profile based on bandwidth, SLO, and quality budget.

- **[lightseekorg/tokenspeed](https://github.com/lightseekorg/tokenspeed)**
    - TokenSpeed is an open-source LLM inference engine for agentic workloads that separates a C++ control plane (a finite-state machine for request and KV-cache lifecycle) from a Python execution plane, with pluggable kernels.

- **[jmaczan/tiny-vllm](https://github.com/jmaczan/tiny-vllm)**
    - tiny-vllm is a small vLLM-style inference engine in C++ and CUDA, paired with a course that walks you through building it from scratch.
